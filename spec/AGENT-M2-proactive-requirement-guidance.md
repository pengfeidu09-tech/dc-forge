# AGENT-M2 主动式需求引导

## 问题

客户在回答上一轮问题时经常省略宾语。例如机器人刚问“有哪些审批规则和阈值”，客户回答：

> 暂时没有，需要采购价低于市场价的 10%，数量 100 台以上

“暂时没有”应结合上一问理解为“暂时没有明确审批规则”，而不是一个无意义短句。当前实现没有完成指代补全，导致审批问题仍为 `asked`，随后返回“您可以继续补充”的被动兜底文案。

## 行为要求

### 0. Agent 决策边界

上下文补全、原子需求提取、客户信息复述和下一问题选择必须由 LLM Agent 基于结构化提示词完成。应用代码不得通过业务短语正则、关键词表或硬编码问卷顺序推断客户需求。

应用层只负责：

- 向 Agent 提供最近对话、上一问题、当前需求摘要、缺口和已问问题；
- 严格校验 Agent 的结构化输出与原文证据；
- 保存需求状态和问题状态；
- 拒绝重复问题、越权内容和无法通过 schema 的结果；
- Agent 不可用时使用现有冻结规划器做安全兜底，但不得把兜底结果描述为 Agent 理解。

### 1. 上下文省略回答

当当前澄清主题为 `approval` 时，句首的“暂时没有 / 目前没有 / 暂无 / 还没有”必须记录为：

```json
{
  "category": "approval",
  "value": "当前没有明确的金额审批阈值",
  "parameters": {
    "rule_status": "not_defined",
    "needs_internal_confirmation": true
  }
}
```

该规则只能在当前主题明确时使用，不能脱离上下文猜测“没有”的对象。

### 1.1 Skill 动态路由

每一轮需求对话都应由 Skill 路由 Agent 基于最近对话和已提取需求重新判断场景。客户后续补充组织类型或业务场景时，允许从通用采购切换到更具体的 Skill，不能把首轮选择永久锁死。

应用层只能校验 Agent 返回的 Skill ID 是否已注册。路由 Agent 不可用或返回非法 ID 时，沿用上一轮 Skill；不得用行业关键词表替代 Agent 判断。

### 2. 一句话多项需求

上述示例还必须原子化为：

- `budget`：采购价格低于市场价 10%；
- `scope`：采购数量 100 台以上。

每项必须保留原文证据和结构化参数，例如折扣百分比、数量、单位和上下限方向。

### 3. 客户侧追问顺序

提示词应引导 Agent 在早期需求发现中优先收集易回答的业务事实，不直接从内部治理问卷开始：

1. 采购数量和主要使用场景；
2. 车型或能源类型偏好；
3. 总预算或价格口径；
4. 期望交付时间；
5. 售后、质保等服务要求；
6. 审批、数据、安全和系统边界。

每轮最多提出一个紧密相关的问题，问题必须推动需求向前，而不是要求客户自行决定还要补充什么。

### 4. 跳答处理

如果客户没有回答当前问题，但提供了其他有效需求：

- 当前问题标记为 `dismissed`，不原句重复；
- 已提供的信息照常入库；
- 系统选择下一项最有价值的问题继续引导。

不得把未回答的问题错误标记为 `answered`。

### 5. 回复结构

混合回答的客户回复必须包含：

1. 简明复述本轮记录的审批状态、价格和数量；
2. 审批状态为未定义时，提示待内部确认；
3. 主动提出下一问题，例如车辆用途、车型偏好或交付时间。

禁止在仍处于需求发现阶段时返回以下被动文案：

> 目前的信息足够形成初步理解。您可以继续补充审批规则、数据范围或部署要求。

## 验收标准

- “暂时没有，需要采购价低于市场价的 10%，数量 100台以上”生成 approval、budget、scope 三项。
- 原审批问题状态变为 `answered`，并记录当前客户来源 ID。
- 回复复述“低于市场价 10%”和“100 台以上”。
- 回复包含一个新的主动问题，且不再询问同一句审批规则。
- 只说“采购一批汽车”时，首问采购数量和使用场景，而不是审批阈值。
- 客户跳答其他有效需求时，旧问题为 `dismissed` 而不是 `answered`。
