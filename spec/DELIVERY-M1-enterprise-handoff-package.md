# DELIVERY-M1 企业可交付解决方案包

## 目标

生成一套可以直接发送给大型汽车制造企业的售前解决方案包。交付物应能用于客户汇报、技术交流、试点立项和双方验收口径讨论，不依赖客户访问开发仓库。

## 内容依据

对客材料只采用以下已知场景信息：

- 客户类型：大型汽车制造企业
- 业务范围：供应商准入、询比价、采购合规审查
- 当前问题：人工处理较多、采购周期较长、流程留痕不完整
- 建设边界：AI 提供材料检查、分析建议和风险提示，最终审批仍由企业人员和原有系统完成
- 平台入口：飞书客户机器人、企业内部统一售前工作台、客户需求与方案中心
- 系统能力：Requirement Intelligence、业务状态池、企业知识库、MCP 与工具、方案生成、内部评审、客户发布和反馈迭代

当前状态池没有正式 RequirementBaseline，并且存在演示输入形成的冲突内容。交付包不得使用这些冲突内容，不得把待确认需求写成客户正式确认事实。

## 交付文件

交付目录必须包含：

1. `01_DCFORGE_大型汽车制造企业智能招采与采购合规解决方案.pptx`
2. `02_DCFORGE_解决方案建议书.pdf`
3. `03_DCFORGE_解决方案建议书.html`
4. `04_DCFORGE_实施与验收计划.xlsx`
5. `05_DCFORGE_部署安全与集成边界.md`
6. `06_DCFORGE_演示与操作手册.md`
7. `README_交付说明.md`
8. `manifest.json`

同时生成包含上述文件的 ZIP 包。

## PPT 结构

PPT 至少包含以下内容：

1. 封面与材料状态
2. 客户现状理解
3. 本次建议聚焦的问题
4. 建设目标与验收口径说明
5. 方案总览
6. 完整业务闭环
7. 供应商准入场景
8. 询比价场景
9. 采购合规审查场景
10. Agent、知识库、MCP 与工具架构
11. 业务状态池和需求版本机制
12. 企业员工和客户双入口
13. 数据、安全与人工决策边界
14. 分阶段实施路线
15. 建议验收指标
16. 三档建设范围
17. 项目风险与双方待确认事项
18. 下一步工作安排

## 诚实性边界

- 所有指标必须标注为建议值或待验证值，不得描述为已经实现的业务成果。
- 不使用内部评审分数、资产 ID、工具内部名称、飞书 open_id、tenant_key、chat_id、项目内部 ID 或本地路径。
- 不使用当前状态池中的学校、教育、具体车型或采购数量等冲突演示内容。
- 不承诺 AI 自动完成供应商准入、采购审批、定标或付款。
- 历史案例只能作为参考，不得表述为当前客户成果。

## 技术要求

- PPTX、XLSX 和 HTML 可编辑。
- PDF 适合直接发送和打印。
- HTML 不依赖外部网络资源。
- `manifest.json` 记录版本、生成时间、文件大小、SHA-256 和内容边界。
- ZIP 解压后可独立阅读，不依赖源码和本地服务。

## 验收标准

1. 所有约定文件存在且不是空文件。
2. PPT 至少 18 页，包含方案、架构、实施、验收和风险。
3. HTML 和 PPT 不包含内部标识或冲突演示内容。
4. PDF 有效且可打开。
5. XLSX 包含实施计划、验收指标、接口清单和双方待办。
6. ZIP 包含全部交付文件和清单。
7. 清单中的 SHA-256 与实际文件一致。
8. 新增测试和 `tests/test_contracts.py` 通过。
