# PRESALES-M5 草稿生成前置步骤自动化

## 背景

统一售前工作台已经允许基于最新 `RequirementState` 生成演示草稿，但调用方仍需先手工创建知识研究快照。当飞书项目首次进入工作台时，直接生成草稿会返回 `knowledge research snapshot is required`。此外，客户已经给出价格、数量或审批条件时，这些明确规则尚未归一化为 V2 可识别的审查规则语义。

研究快照和编译器选择属于服务端编排职责，不应成为演示人员需要理解和配置的前置步骤。

## 目标

`POST /presales/projects/{project_id}/drafts` 在项目已有需求状态但尚无研究快照时，应自动完成知识研究，并把明确的客户规则映射为 V2 编译语义，生成可继续评审的演示草稿。

## 行为约束

1. 已有研究快照时继续使用最新版本，不重复自动研究。
2. 没有研究快照时，服务根据项目行业和当前有效需求生成研究查询，调用现有知识服务并持久化 `ResearchSnapshot`。
3. 自动研究必须保留真实检索结果和引用；没有结果时允许保存空结果，不得虚构案例、来源或业务成果。
4. 显式 `POST /research` 接口保留，用于员工补充查询条件和生成后续研究版本。
5. 正式 Baseline 和演示 RequirementState 都适用自动研究。
6. 客户明确给出的 `business_rule`、`budget` 或 `approval` 条件，在演示 `ProcessSpec` 中归一化为“审查规则”编译语义；该映射不得声称客户已提供制度文档。
7. 新草稿仍只调用 `compile_solution_v2` 或正式 Baseline 的 V2 handoff，不得回退旧编译器。
8. 若归一化后仍没有可执行 V2 资产，保留 V2 的证据边界，不虚构复用决策。
9. 草稿警告必须说明自动研究和演示预览事实，避免把缺少证据的方案描述为已验证成果。

## 验收标准

1. 无研究快照、有最新 RequirementState 时，直接请求草稿接口返回 `201`。
2. 请求后工作区包含自动生成的研究快照，草稿引用该研究版本。
3. 稀疏需求包含明确采购规则时，可由 V2 返回三套方案且不调用旧编译器。
4. 已有研究快照的既有正式方案生成行为保持不变。
5. 新测试、`tests/solution` 和 `tests/test_contracts.py` 通过。
