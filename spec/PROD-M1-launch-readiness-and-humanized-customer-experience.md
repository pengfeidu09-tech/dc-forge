# PROD-M1 上线就绪与自然对客体验

## 目标

在不修改公共合同、流程引擎、运行时和前端工程的前提下，补齐客户闭环上线前最直接的风险：配置误用、页面缓存与嵌入、无边界输入、客户访问链接长期有效、模型临时故障，以及机械化对客回复。

本规格覆盖飞书客户机器人、客户需求与方案中心、企业客户工作台和 OpenAI 兼容模型调用。

## 范围

### 生产就绪检查

- 保留 `/health` 作为兼容入口。
- 新增 `/health/live`，只说明进程可以响应。
- 新增 `/health/ready`，返回每项配置的状态，不返回密钥或令牌值。
- 当 `DCFORGE_PRODUCTION_MODE=true` 时，以下条件任一不满足，ready 返回 503：
  - `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 均已配置。
  - `REQUIREMENT_REPOSITORY_ROOT` 和 `CUSTOMER_ENGAGEMENT_ROOT` 位于 Git 工作树之外，且目录可写。
  - `CUSTOMER_PORTAL_BASE_URL` 使用 HTTPS，且不是 localhost 或回环地址。
  - `CUSTOMER_ENGAGEMENT_INTERNAL_TOKEN` 至少 32 个字符。
  - `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 已配置。
  - `FEISHU_INTERNAL_OPEN_IDS` 至少包含一个内部员工 open_id。
- `FEISHU_ALLOWED_OPEN_ID` 在生产环境中不是阻塞项，但检查结果要提醒它会把机器人限制为单个客户。
- 文件存储当前只承诺单进程写入。若 `WEB_CONCURRENCY` 大于 1，生产 ready 返回 503。

### HTTP 安全边界

客户页面、客户数据接口和内部客户工作台接口返回以下响应头：

- `Cache-Control: no-store`
- `Content-Security-Policy`，只允许页面自身资源和脚本
- `Referrer-Policy: no-referrer`
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`

页面不得把客户访问令牌写入路径、查询参数、页面源码或服务端日志。令牌继续通过 URL Fragment 进入浏览器，再通过请求头发送。

### 输入边界与基础限流

- 发布人名称最多 120 个字符。
- 客户确认备注最多 2000 个字符。
- 客户反馈最多 4000 个字符，不能为空。
- 单次确认接收和拒绝的需求项各不超过 200 个，且不得重复。
- 客户确认和反馈接口按访问标识与客户端地址限流。
- 限流参数由环境变量控制，默认每 60 秒最多 10 次。
- 超限返回 429 和自然、简短的提示，不返回内部异常。
- 该限流器只提供单进程保护。多实例部署仍应在 API 网关执行分布式限流。

### 客户访问有效期

- 新建客户访问令牌默认 30 天有效，可通过 `CUSTOMER_ACCESS_TTL_DAYS` 配置。
- `access.json` 保存 `expires_at`。
- 读取旧数据时，如果没有 `expires_at`，以 `created_at` 加当前 TTL 迁移并写回。
- 过期访问标识或令牌统一表现为项目不存在，不暴露过期原因。
- 轮换令牌时同时更新 `created_at` 和 `expires_at`。

### 模型调用稳定性

- `LLMResponse.warnings` 使用独立列表默认值。
- 429、502、503、504 最多进行有限重试。
- 只接受短 `Retry-After`，不因服务端返回较大等待时间而长时间阻塞。
- 所有非 2xx 状态都返回明确但不泄密的 warning。
- 非 JSON 或结构不完整的响应继续降级，不向客户暴露 API Key、原始响应体或调用地址。

### 自然对客文案

- 删除连续出现的“感谢您的说明”“进一步梳理适合贵司的方案”等固定开场。
- 有待补充信息时直接问一个问题，例如“我先确认一个信息：采购项目有哪些人工审批规则和阈值？”
- 当前没有待补充问题时，说明已形成初步理解，并告诉客户可以补充哪些实际信息。
- 模型输出含内部状态字段时，使用简短的业务提示，不复述内部字段。
- 不声称已经达成 ROI、周期缩短、合规提升或客户确认，除非系统存在对应事实。

### 冲突需求确认

- 普通需求继续使用复选框。
- 同一 `choice_group` 下的冲突项使用单选框。
- 页面提示客户这些选项存在冲突，只能选择一项。
- 提交时，同组未选项进入拒绝列表，避免同时确认互斥需求。

## 不在本次范围

- 不修改 `backend/app/contracts/`、`backend/app/process/`、`backend/app/runtime/`、`data/fixtures/` 或 `frontend/`。
- 不引入数据库、Redis、网关、进程管理器或证书服务。
- 不处理与本规格无关的浮点精度测试失败。
- 不把文件仓库描述为支持多 worker 或多实例并发写入。

## 验收标准

1. 生产配置缺失时 `/health/ready` 返回 503，且响应中没有任何密钥值。
2. 合法的本地开发配置不会被严格生产规则阻断。
3. 客户页面和接口带有 no-store、禁止嵌入和禁止 referrer 的安全头。
4. 过长输入返回 422，短时间重复提交超过阈值返回 429。
5. 旧访问数据能迁移；过期令牌不可访问；轮换后重新获得完整有效期。
6. 模型临时返回 429 或 503 时会有限重试，永久失败时安全降级。
7. 飞书需求追问和内部字段拦截后的客户回复不再使用机械化感谢模板。
8. 冲突需求在客户页面显示为单选项，提交逻辑不会同时接受同一冲突组的多个候选。
9. 新增测试通过，`tests/test_contracts.py` 通过。
