# PORTAL-M8：Internal Console 数据库项目列表

## 背景

Internal Console 当前把整份工作台状态保存在浏览器 `sessionStorage`，并在加载汽车采购示例时生成带时间戳的 `project_id`。用户看到的是难以理解的技术标识；刷新、换浏览器或换设备后也无法从后端找回分析记录。页面同时缺少明确的资料文件上传入口。

## 产品目标

1. Internal Console 使用 `DCFORGE_DATABASE_PATH` 指向的统一 SQLite 数据库保存项目目录、原始资料和工作台快照。
2. 页面不再展示或允许编辑技术 `project_id`。
3. 页面展示可选择的分析记录列表：汽车采购 Demo 固定为第一项；后续分析记录按创建顺序显示为“需求分析 2”“需求分析 3”……。
4. 点击“开始需求分析”时，后端先原子创建下一条分析记录并分配不可见的项目 ID，再用该项目 ID 执行需求分析；创建成功的记录即使分析失败也必须保留，避免用户输入丢失。
5. 每次需求分析、确认、方案生成、反馈分析和重编译完成后，把最新工作台快照保存到数据库。选择历史记录时恢复其原始资料和已有成果。
6. 保留文本输入，并提供文本资料上传。首版接受 UTF-8 文本类文件（`.txt`、`.md`、`.json`、`.csv`），把文件内容加入“需求 / 招标材料”；不得声称已解析 PDF、Word 等未实现格式。

## 数据规则

- 数据表使用单调递增 `sequence` 作为展示顺序。
- Demo 使用 `sequence = 1` 和稳定的内部 ID；初始化必须幂等，不能在每次启动时重复插入。
- 用户记录的内部 ID 由服务端根据序号生成，前端不得生成或展示。
- 项目快照至少保存：原始资料、需求分析、需求基线、方案、反馈差异和重编译结果。
- 项目列表按 `sequence` 升序返回，Demo 永远排在第一项。
- SQLite 默认路径沿用 `DCFORGE_DATABASE_PATH`；未配置时使用仓库外的用户数据目录默认值。

## 交互规则

1. 页面启动时读取项目列表并默认选中最近一次使用的记录；没有本地选择时选中 Demo。
2. 选择 Demo 或历史记录后恢复数据库中的快照。
3. “开始需求分析”始终基于当前编辑区内容创建一条新记录，不覆盖 Demo 或历史记录。
4. 创建后立即切换到新记录；分析期间按钮显示加载状态并禁止重复提交。
5. 上传文件只读取本地文本内容，不自动发起独立网络上传；内容随“开始需求分析”一起保存。
6. “后端已连接”仍只表示健康检查成功；项目列表加载失败必须显示真实错误。

## API

- `GET /internal-console/projects`：初始化 Demo 并返回项目列表。
- `POST /internal-console/projects`：创建下一条分析记录，服务端分配序号、标题和项目 ID。
- `PUT /internal-console/projects/{project_id}`：保存该项目的最新工作台快照。

## 验收标准

1. SQLite 仓库测试证明 Demo 幂等、排序稳定、用户项目从序号 2 开始且重启后仍存在。
2. API 测试证明创建项目时忽略前端技术 ID，并能保存/恢复快照。
3. 前端不再包含“项目 ID”输入框，包含分析记录列表和文本资料上传。
4. 连续两次点击分析所使用的项目由服务端依次编号，不使用 `Date.now()`。
5. Internal Console 默认服务使用统一 SQLite RequirementRepository，不再要求 `INTERNAL_CONSOLE_DATA_ROOT`。
6. 新测试、相关 Internal Console/平台测试、前端测试与构建、`tests/test_contracts.py` 通过。
