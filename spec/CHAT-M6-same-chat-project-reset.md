# CHAT-M6 同一飞书会话开启全新项目

## 目标

用户无法创建新飞书群时，可以在当前群中开启一个新的逻辑项目。新项目不读取旧会话、旧 RequirementState、旧 Baseline、旧研究、旧方案或旧客户访问链接。

## 命令

只有飞书机器人创建者或配置在 `FEISHU_INTERNAL_OPEN_IDS` 中的内部员工可以执行：

```text
/清空记忆 确认
```

同时支持：

```text
/新项目 确认
```

不带“确认”的命令不得改变项目状态。

## 数据处理

- 不物理删除旧项目。
- 当前飞书群保存一个活动逻辑项目映射。
- 首次使用时，活动项目仍是原有的 `feishu:{tenant_key}:{chat_id}`。
- 执行重置后，新项目使用独立项目 ID 和独立客户访问令牌。
- 旧项目保留在内部工作台中，供审计和恢复使用。
- 机器人进程内的旧聊天记忆不再参与新项目对话。
- 新项目自动进入统一售前工作台。

## 客户回复

成功后回复：

```text
已在当前群开启全新项目。旧项目已归档保留，不会参与新的需求分析。请重新发送客户背景和本次项目范围。
```

## 验收标准

1. 同一 tenant 和 chat 在重置前后得到不同项目 ID。
2. 映射在进程重启后仍然有效。
3. 新消息只写入新项目。
4. 新项目没有旧消息、RequirementState、Baseline 或客户访问令牌。
5. 未授权用户不能执行重置。
6. 新增测试、`tests/test_contracts.py` 和既有飞书测试通过。
