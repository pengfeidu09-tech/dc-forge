# DATA-M2 知识包内容质量与一致性完善

## 背景

`企业客户需求全过程知识管理系统_FINAL_COMPLETE` 已具备目录骨架和一套车辆采购全过程结构化案例，但旧的“华东新程汽车项目”仍存在明显的数据质量问题：

- 公司能力文档、工程说明和部分接口说明只有 1—5 行；
- 7 份业务文档只有文件名和“模拟业务资料”占位句；
- 12 份会议纪要除标题外内容完全相同，无法形成真实的决策链；
- 30 条企业微信记录中大量使用“第 N 阶段”模板，责任、结论和关联对象不明确；
- `05_沟通记录` 与 `04_沟通记录` 内容重复且编号冲突；
- `knowledge_chunks.jsonl` 有 500 行，但正文只有一个唯一值，数量不能代表知识质量；
- Skill、MCP 和演示说明只有名称，没有可执行边界、输入输出和证据要求。

这些问题会导致 RAG 检索噪声高、业务对象不可追溯、演示结果失真。本任务目标是把资料包从“目录样例”提升为“可读、可检索、可追溯的模拟业务知识包”。

## 数据性质和时间线

- 华东新程、人员、供应商、项目金额、项目过程、会议、验收指标均为 `synthetic_demo`。
- 当前数据制作日期为 `2026-08-14`；之后的会议、合同、实施、验收与复盘均属于 `simulated_future_scenario`。
- 模拟指标只能描述为验收口径、演示结果或剧本结果，不得描述为真实经营成果。

## 完善范围

### 1. 通用知识

完善以下内容，使其具备适用场景、能力边界、输入输出、流程、风险与指标口径：

- `01_公司能力知识库/*.md`
- `02_行业解决方案库/*.md`
- `05_AI_Agent/*`
- `07_Skill技能库/*.yaml`
- `08_工程说明/*.md`

### 2. 华东新程项目

建立稳定的 `PRJ-KM-001` 项目主索引，并完善：

- 客户画像、组织角色和数据边界；
- `REQ-001`、`REQ-002`、`REQ-003` 的版本、优先级、验收标准和来源；
- 12 场各有独立议题、争议、决策、风险与行动项的会议纪要；
- 采购需求书、技术规格书、供应商评审、招标文件、合同草案、验收报告、项目复盘和数据分类规范；
- 有明确发送方、接收方、主题、日期、结论和关联对象的邮件；
- 有业务语义而非序号模板的企业微信记录及完整时间线。

### 3. RAG 数据

- 删除 500 条同文重复的伪知识块，按实际来源文件重建阶段级知识块；
- 知识块包含 `chunk_id`、数据性质、项目 ID、来源类型、来源 ID、来源路径、关联对象、标签和可独立理解的正文；
- 通讯知识块与企微/邮件源记录保持一一可追溯；
- 更新元数据说明，明确字段、分块规则、去重规则和诚实性规则。
- 图片版PDF必须有资料治理说明和页级OCR摘要；营销指标、匿名成功案例与产品能力声明统一标记为 `unverified_marketing_claim` 和 `reference_only`，不得进入权威事实回答。

### 4. 目录治理

- `04_沟通记录` 为唯一沟通目录；
- 删除完全重复且编号错误的 `05_沟通记录`；
- `05_业务文档` 只存放正式业务文档；
- README 和项目主索引说明阅读入口和对象关联方式。

## 内容质量标准

1. 所有 Markdown 文件正文不少于 400 个字符，不允许使用占位句堆行数。
2. 业务文档至少包含：文档元数据、背景/目标、范围、主体内容、关联对象、风险或约束、确认/审批信息。
3. 会议纪要至少包含：元数据、参会角色、背景、讨论要点、争议或取舍、决策、行动项、风险、关联对象；12 场会议不得复用相同正文。
4. 行动项包含负责人、截止日期和状态；未来日期必须保留模拟剧本标识。
5. 需求、会议、沟通和业务文档使用稳定 ID，并能通过 `project_master.json` 相互发现。
6. 企业微信不得出现“针对第 N 阶段”“确认下一步行动”等无业务语义模板。
7. RAG 知识块正文唯一，不通过复制相同内容制造数量；每块不少于 80 个字符。
8. Skill 必须包含版本、描述、适用场景、输入、步骤、证据要求、守则和结构化输出。
9. MCP 工具必须定义用途、输入结构、输出结构、权限和审计要求。
10. 不修改禁止范围内的后端、流程、运行时、fixtures 或前端。
11. 无文本层的图片PDF按页可检索，并保留页码、OCR状态、资料权威级别与声明验证状态。

## 验收

- 新质量测试、DATA-M1 全过程数据测试和 `tests/test_contracts.py` 均通过；
- 所有 JSON、JSONL、YAML 可解析；
- `git diff --check` 通过，并确认只改动本任务范围。
