# PLATFORM-M1：内外门户与方案链路收敛

## 背景

当前根门户直接展示仓库内置的模拟采购项目，并通过旧版 `compile_solution` 生成三套方案。统一售前工作台则优先使用 Solution Intelligence V2，但在资产无法匹配时仍会回退旧编译器。客户专属页面会同时展示三套内部候选方案，飞书 Agent 的 Tool 权限写死在代码中，员工无法配置 Skill。

这些行为混淆了内部作业、客户交付和演示数据，必须收敛为一套正式链路。

## 产品边界

### 对内

- 根页面是内部工具入口，不展示任何内置项目、指标、供应商、合同或方案样例。
- 业务数据只能由服务端数据库/API 提供；前端不得打包 mock 业务数据。
- 需求状态与基线、客户会话与访问链接、售前项目与方案版本、案例和 Agent 配置统一存入 `DCFORGE_DATABASE_PATH` 指向的 SQLite 数据库。
- 未配置数据库路径时使用用户数据目录下的仓库外默认数据库；正式运行不再依赖 `REQUIREMENT_REPOSITORY_ROOT`、`CUSTOMER_ENGAGEMENT_ROOT` 或 `PRESALES_ORCHESTRATION_ROOT` 文件目录。
- 员工在统一售前工作台维护需求、同步进度、客户资料、历年案例、知识研究和方案版本。
- 售前知识研究优先检索 SQLite 案例库并把命中案例写入方案成果引用，不再依赖内置参考项目 ID。
- Solution Intelligence V2 始终生成三套内部候选方案，并给出默认推荐方案。
- 员工可以选择其他候选方案，也可以对选定方案做结构化人工修改；选择和修改都形成修订记录并使旧审批失效。
- Tool 与 Skill 必须有可查询目录；飞书客户 Agent 和内部 Agent 分别保存启用白名单。

### 对外

- 每个客户项目通过带访问令牌的专属 URL 访问。
- 客户页面只展示当前发布的一套方案，不展示三套候选或内部评分。
- 客户页面展示需求确认状态和与内部同源的公开进度。
- 客户反馈继续进入 RequirementState 版本链，不直接覆盖已确认事实。

## 方案规则

1. 新草稿只调用 `compile_solution_v2` 或正式基线的 V2 handoff。
2. 不允许回退到旧 `compile_solution`。
3. 草稿保存 `selected_solution_id`；初始值使用 `recommended_solution_id`。
4. 员工改选或修改方案后增加 `solution_revision` 并写入审计记录。
5. 发布严格使用草稿中当前选定、当前修订且已批准的一套方案，不在发布时重新编译。

## Agent 配置

- 配置存入工作区 SQLite 数据库，不写入前端、环境变量或仓库样例。
- 至少提供 `feishu-customer` 和 `feishu-internal` 两个 Agent profile。
- Tool 白名单在执行前强制过滤；Skill 白名单作为 Agent 规划上下文，不得把未启用 Skill 告知模型。
- 新版 Agent 配置目录只暴露正式的数据库案例检索与公开能力检索，不向员工展示旧模拟项目、供应商、合同或财务 Tool。
- 客户 Agent 仍受客户安全上限约束，配置不能扩大到内部 Tool。

## 验收标准

1. 根前端不再引用旧企业驾驶舱 composable、组件或 mock 数据。
2. 根页面只展示工具入口和内部智能引擎控制台。
3. 售前编排运行链路中不存在旧编译器回退。
4. 草稿支持方案选择和结构化编辑，审批绑定最新方案修订。
5. 客户数据接口返回单个 `plan` 和 `progress`，客户前端不再渲染三方案 Tabs。
6. Tool/Skill 目录与 Agent 白名单可通过内部 API 查询和更新，并持久化到 SQLite。
7. 飞书 Agent 实际执行 Tool 前应用数据库白名单。
8. 新测试、既有售前/客户测试、前端测试、构建和 `tests/test_contracts.py` 通过。
9. 三个正式运行时服务使用同一个 SQLite 数据库，新增或更新业务记录不会生成 JSON 业务文件。
10. 新建售前项目和知识研究不会注入演示项目或预填业务样例，数据库案例可以被研究链路检索并进入方案引用。
