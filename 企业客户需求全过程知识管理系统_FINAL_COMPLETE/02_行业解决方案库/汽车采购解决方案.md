# 汽车采购全过程知识管理解决方案

## 方案说明

本方案面向整车、零部件、经销贸易、租赁与出行企业，目标是将客户或内部采购需求与寻源、报价、合同、车辆、VIN、物流、验收、资金和售后信息串成可追溯链。文中的企业、数字和结果是模拟示例，不能作为真实客户案例或收益承诺。

## 业务问题

汽车采购兼具大额交易、配置复杂、分批履约和单车唯一标识等特点。客户最初往往只给出数量和车型方向，后续会补充续航、颜色、地区、首批交期、账期和资料要求。如果报价和合同没有关联具体需求版本，就会出现“价格针对哪版需求”无法说明的问题。

供应侧也不是简单的一对一关系。同一车型可能由多家经销商、区域渠道和贸易商提供，不同报价在数量、库存、VIN锁定、交期、付款和发票条件上不同，最终采购方案可能由多家供应商组合。进入履约后还要从订单下沉到VIN，才能处理车辆配置、随车资料、运输损伤、验收异常和售后追溯。

## 中心对象

系统以 Customer Requirement 为中心，而不是以合同为起点。需求记录客户、场景、数量、车型、预算、地区、时间和决策条件；每次变化产生 Requirement Version。供应商询价、采购方案、客户方案、报价、审批、合同和订单都必须关联确认基线。

项目主链为：需求与版本 → 澄清与可行性 → 供应商询价和报价 → 比价与采购组合 → 客户方案和报价 → 谈判审批 → 销售与采购合同 → 订单和VIN → 物流交付验收 → 发票收付款 → 利润 → 售后复购与复盘。

## 五条并行信息流

需求流回答客户要什么以及最终是否满足；商品流追踪供应商、SKU、VIN、物流和交付；商务流管理询价、报价、谈判、合同和订单；资金流管理发票、应收应付、收付款和利润；信息流保存电话、微信、邮件、会议、审批、异常和复盘。五条流共享稳定ID，避免依靠文件名或人工记忆关联。

## 数据设计要点

车型与SKU需要区分。车型描述品牌、车系、年款和技术参数，SKU进一步固定配置、颜色和内饰。车辆对象必须使用唯一VIN，并关联供应商、采购单、销售订单和交付批次。合同、订单、交付、发票和付款通常是一对多关系，系统应支持分批而非假定一次完成。

利润需要从收入逐项扣除车辆采购、物流、保险、上牌、金融、佣金和售后成本，且每个成本项有证据。意向复购只能记录为Lead，不能提前写成成交。模拟项目的交付率、满意度和利润率必须明确为演示口径。

## 实施路径

第一阶段统一ID、元数据、需求版本和权限；第二阶段选择一个车辆采购项目构建端到端样板；第三阶段接入SRM、合同、物流和财务数据；第四阶段建立RAG检索、规则审查和异常Agent；第五阶段用真实授权数据独立验收。任何自动建议都不替代采购、法务、财务和验收人员的正式决定。

## 风险控制

主要风险包括需求版本漂移、供应商报价失效、VIN重复或错配、权限泄露、金额不守恒和模型编造结论。应通过基线冻结、有效期校验、唯一约束、检索前权限过滤、对账规则和证据不足提示控制。完整模拟样例见项目 `PRJ-AUTO-001`。
